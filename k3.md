# Vervellum review (k3)

A read of the whole tree: `Sources/VervellumKit/Core` (the shared pipeline),
the macOS front end in `Vervellum/`, the Linux front end in
`Sources/VervellumKit/Linux`, packaging, CI, and the 190 shared tests (all pass
locally, Swift 6.2.3).

Overall: this is an unusually disciplined codebase. The threat model is real and
consistently enforced (no model-written URLs, no redirect following, no provider
error text in logs, Keychain-only keys). The portability rule is held. Comments
explain *why*. What follows is what is actually wrong, what is missing, and what
would make it better — ordered by how much a user would notice.

---

## 1. Bugs

### B1. `# C#` renders as "C" — heading parser strips non-closing hashes
`MarkdownParser.heading` strips *any* trailing run of `#` as an "ATX closing
sequence". A closing sequence must be preceded by whitespace; without that check
the heading `# C#` loses its final `#`, and `# Version 2#` becomes `Version 2`.
Reproduced with a test (`MarkdownParser.parse("# C#").first?.text == "C"`).
Fix: only strip the trailing run when the character before it is a space.
**Severity: real but narrow.** Models rarely end headings in `#`, but "C#" is a
very plausible heading in a programming answer.

### B2. Asking a question while the history list is open runs the research invisibly
`PanelRootView.submit` clears `showsHelp` on `.ask` / `.direct` but not
`showsHistory`. The composer stays live while the history view is open, so
typing a question there and hitting Return starts a full research run behind
the history list — no trail, no streamed answer, just the send button turning
into Stop. Fix: `showsHistory = false` in those two cases.

### B3. The thread auto-scrolls on every streamed token, even while the user is reading
`PanelRootView.thread` scrolls to the bottom anchor on every change of
`turns.last?.answer`. During a 30-second answer, scrolling up to re-read the
first paragraph yanks you back to the bottom on the next token. Every chat UI
solves this the same way: auto-scroll only while pinned to the bottom, and show
a "jump to latest" affordance when not. There is no scroll-position tracking at
all. **This is the single most user-visible defect.**

### B4. `ThreadLibrary.search` lowercases every answer on every keystroke
`HistoryView.results` calls `store.library.search(query)` from a computed
property, which runs on every render. The search scans `turn.question` and
`turn.answer` with `lowercased().contains(...)` — with 200 threads × multi-KB
answers that is megabytes of lowercasing per keystroke in the search field.
Fix: search title + question only (the answer hit rate is not worth the cost),
or precompute a lowercased index when the library changes, not per render.

### B5. Reasoning-model streams show dead air before the first token
`ChatCompletionsClient.streamText` reads only `delta.content`. Reasoning models
(GLM-5, DeepSeek-R1, o-series via gateways) stream `delta.reasoning_content`
first, sometimes for tens of seconds. The user sees "Writing the answer" and a
blinking caret while the model is audibly working. Not a crash, but it reads as
a hang. Fix: count reasoning deltas as progress (collapse them into a "thinking"
line in the process trail, or at least surface "model is thinking" once the
first reasoning delta arrives).

### B6. `retry` on an old failed turn silently re-asks at the end — the failure row stays
`ResearchEngine.retry` on a non-last turn appends a *new* turn but leaves the
old failed one in place. That is deliberate ("where the answer belongs"), but
the failed turn then keeps showing "Try again" forever, inviting a duplicate.
Minor: mark the old turn retried, or at least drop its retry affordance once a
newer turn exists for the same question.

## 2. Performance

### P1. macOS re-renders the whole panel per streamed token; Linux throttles, macOS does not
`ResearchEngine.apply` assigns to `@Published thread` on every SSE delta.
Each publish re-renders the thread, and the last turn's render re-parses the
*entire* answer markdown (`MarkdownParser.parse`), re-runs the citation regex
per block (`MarkdownText.mask` → `CitationValidator.validate`), and re-runs
`TurnView.validation` on the whole answer. For an n-token answer that is O(n²)
total parsing work. The Linux front end already solved exactly this:
`LinuxPanel.apply` redraws answer-only changes at 10 Hz and structural changes
immediately. Port that idea into `ResearchEngine` (coalesce answer-only
snapshots, flush trailing) and the macOS panel gets the same behaviour for free
in every view. **Biggest perf win available.**

### P2. `TurnView.validation` recomputes on every render
A computed property running a regex pass over the full answer. Cheap per call,
but it runs per token per visible turn (see P1). The P1 throttle mostly covers
it; if more is needed, memoize per answer string.

### P3. `ComposerView.height` builds a full text stack per keystroke
`NSTextStorage` + `NSLayoutManager` + layout, per keystroke and per geometry
pass. Bounded and small (questions are short); fine in practice. Note only.

### P4. `LazyVStack` + `fixedSize(horizontal: false, vertical: true)` everywhere
Each markdown block is eager-height; a 50-turn thread re-laid-out on each new
turn is fine at 10 Hz, but the per-token case (P1) makes this expensive.
No action beyond P1.

## 3. General issues / robustness

- **G1. No transient-failure retry.** A 429 or a dropped connection fails the
  whole turn; the plan and assess calls are exactly the ones worth one retry
  with backoff (they are small and idempotent). The streamed answer can keep
  failing fast.
- **G2. No token-usage visibility.** `stream_options: {include_usage: true}` is
  supported by OpenAI and most compatible gateways; showing "2.1k tokens" in the
  collapsed trail is cheap and makes cost visible. Unknown parameters are
  ignored by conforming servers, so this is low-risk — but verify against z.ai
  before shipping.
- **G3. `vervellum --ask` has no machine-readable output.** `StandardErrorLog`'s
  comment already anticipates a `--json` mode. For a tool whose CLI is
  script-friendly, `--json` emitting the turn (answer, findings, sources,
  notices) would make it composable.
- **G4. Linux parity gaps are stubbed, not built.** `/history` and `/settings`
  on Linux print "macOS-only" notices. The thread archive is shared, so a
  history browser on Linux is pure UI work; settings could at least round-trip
  the JSON file. Also missing on Linux: clickable follow-ups, the Copy affordance,
  retry buttons.
- **G5. `ThreadArchive` warning text goes to stderr only.** If the threads file
  is newer than the build (read-only mode), the macOS app has no UI surface for
  that warning — the user just sees history that never updates. `HistoryView`
  could show a "read-only (newer format)" banner; `ThreadStore.isReadOnly` is
  already exposed and unused in the UI.
- **G6. `AssessmentParser` rounds fractional citations** (`Int(exactly:
  number.rounded())` admits 2.7 → 3). A model emitting `2.5` as a source number
  gets silently re-pointed at source 3. Reject non-integral Doubles instead.
- **G7. Accessibility grant-loss alert is the only re-entry to the feature.**
  After an update resets the grant, the shortcut throws an alert every press
  until the user either re-grants or disables the shortcut. Consider a "don't
  ask again, just open the panel without selection" escape — small, but it
  defuses a genuinely annoying loop.

## 4. Missing features (user-facing)

- **F1. Markdown tables.** Models emit tables constantly; `MarkdownParser`
  renders them as raw pipe text. A table block (header + delimiter row as the
  trigger, per CommonMark), rendered as a real grid on macOS and a monospace
  aligned block in Pango, is the largest *rendering* gap. Parser is shared and
  unit-testable.
- **F2. "Ask again" / "Edit & re-ask" on completed turns.** Retry exists only
  for failures. A completed answer you want re-run (new model, rephrased plan)
  means retyping. `ResearchEngine.retry` already handles the mechanics.
- **F3. Live elapsed time while running.** The trail shows the stage; a ticking
  `8s`, `19s`… next to it turns "is it stuck?" into information. `TimelineView`
  makes this three lines on macOS.
- **F4. Completion signal when the panel is hidden.** Dismissal mid-run is
  supported (the run continues), but nothing tells you it finished. A subtle
  sound or a brief menu-bar icon change (the status item already exists) closes
  the loop.
- **F5. Shell-style global recall.** `↑`/`↓` walk this thread's questions only.
  Walking all threads' questions (newest first, deduped) matches what a shell
  does and costs a `ThreadStore` lookup.
- **F6. Export a thread as markdown.** Per-turn Copy exists; a whole-thread
  export (⌘S → NSSavePanel) is a natural extension of `TranscriptFormatter`.
- **F7. Example questions in the empty state.** Three clickable chips ("What's
  new in Swift 6.3?", …) that seed the composer. Onboarding that doubles as a
  demo of what the tool is *for*.
- **F8. Keyboard navigation in History.** The search field takes focus, but
  ↑/↓ don't walk results and ⌫ doesn't delete. Spotlight muscle memory.
- **F9. `--json` for the Linux CLI** (see G3).
- **F10. Streaming of the *planning* stage is absent by design, but the plan
  call is the longest silent gap** (plan → connect → first search can be 5–10s).
  The trail already names the stage; consider an indeterminate shimmer on the
  trail card while waiting — purely cosmetic, sells aliveness.

## 5. Visual / layout

- **V1. Scroll-follow pill** (see B3): when the user scrolls up during a stream,
  show a small "↓ latest" pill at the bottom of the thread.
- **V2. Verdict strip in the collapsed trail.** The findings distribution ("3
  supported · 1 mixed") exists in `FindingsView`; echoing a tiny coloured dot row
  in the collapsed `ProcessTrailView` summary would make evidential health
  visible at a glance without expanding anything.
- **V3. Source rows reveal their snippet on hover only.** A trackpad user who
  never hovers (screen reader, keyboard nav) never sees the "Search summary —
  not the full page" line. Consider an always-visible domain + snippet-expand
  chevron.
- **V4. The composer maxes at ~6 lines and then scrolls internally** — fine —
  but there is no visible affordance that it scrolled; a fade at the top edge
  when scrolled would help. Minor.
- **V5. PangoMarkup quote blocks are only a colour change** — no left bar like
  macOS. A `│`-prefixed monospace line would match. Minor parity.

## 6. Delightful / novel ideas

- **D1. "Watch it think."** When the model streams `reasoning_content`, render
  it dimmed and collapsed in the trail ("Thinking…" → expandable). This is the
  rare case where a feature is *both* delightful and honest — it shows real
  process instead of a spinner. (Depends on B5 parsing.)
- **D2. Completion tick.** A soft `NSSound` pop + status-item flash when a run
  finishes while the panel is hidden (F4). Two lines each, big feel.
- **D3. Verdict-coloured thread dots in History.** Each row gets a dot: green if
  all findings supported, amber if any mixed/insufficient, red if contradicted.
  Turns the history list into an evidential-health overview for free.
- **D4. `/digest` command.** Summarize the *current thread's* unsettled claims
  into one compact brief (from `unsettled` data already in `ResearchContext`),
  answered `/direct`-style without search. Zero new infrastructure, uses data
  already collected, very on-brand for "the evidence is the product".
- **D5. Citation popover.** Hovering an inline `[3]` shows the source title +
  snippet in a popover instead of just a tooltip. AppKit popover anchoring from
  an AttributedString link is fiddly; a click-to-open-QuickLook-style popover
  anchored at the source list row would be nearly free.
- **D6. Idle easter egg in the empty state:** a faint rotating one-liner of what
  the tool refused to say confidently ("Not established" examples). Quirky, but
  advertises the core value better than any marketing line. Keep it subtle.

## 7. What I implemented from this list

Each on its own branch in L-K-M/Vervellum, each with a PR against main. (The
first round went from the fork while the token had no push access; those PRs
are closed, superseded by the ones below. A pre-existing CI break on main —
toolchain drift made `(raw as? UInt).map(Int.init)` ambiguous in
ThreadArchiveTests — is fixed in PR #38 and cherry-picked into every branch.):

- **PR #22** `k3/atx-heading-closing-sequence` — **B1**: only strip heading
  trailing `#` runs when preceded by whitespace; regression tests.
- **PR #23** `k3/reject-fractional-citations` — **G6**: `AssessmentParser` no
  longer rounds a fractional source number onto a real source; tests.
- **PR #24** `k3/streaming-render-throttle` — **P1**: coalesce answer-only
  snapshots to ~10 Hz in `ResearchEngine` (mirrors `LinuxPanel`), structural
  changes stay immediate.
- **PR #25** `k3/ask-from-history` — **B2**: asking from the history view
  returns to the thread so the run is visible.
- **PR #31** `k3/scroll-follow` — **B3/V1**: auto-scroll only while pinned to
  the bottom; "Latest" pill while running and unpinned.
- **PR #32** `k3/markdown-tables` — **F1**: pipe tables in `MarkdownParser`,
  a `Grid` renderer on macOS, aligned `<tt>` in Pango; eight parser tests.
- **PR #33** `k3/turn-polish` — **F2/F3**: "Ask again" on completed turns; live
  elapsed clock in the process trail.
- **PR #34** `k3/empty-state-examples` — **F7**: clickable example questions in
  the empty state that seed the composer.
- **PR #35** `k3/history-search-index` — **B4**: `ThreadSearchIndex` — one
  lowercased haystack per thread, rebuilt on library change, not per keystroke.
- **PR #36** `k3/completion-signal` — **F4/D2**: menu-bar busy glyph while a
  run is in flight; soft sound when a run completes with the panel closed.

Not implemented (deliberately): B5/D1 reasoning-content display (needs a live
reasoning model to tune against); D3–D6 (good ideas, need design restraint
more than code); G4 Linux UI parity (large, and untestable from this Linux
box without GTK headers); G1 retry-with-backoff (wants a decision about which
stage failures deserve it); F6 thread export (the per-turn Copy covers most of
it); F8 history keyboard nav (small but easy to get wrong without a Mac).
